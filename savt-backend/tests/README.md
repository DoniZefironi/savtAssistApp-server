# Тесты

Отдельная тестовая БД — никогда не дев/прод. `BITRIX_WEBHOOK_URL` в тестах
всегда пустой (см. `conftest.py`): ни один тест не должен реально писать в
Bitrix, это явное решение, а не забытая настройка. Функции `bitrix_service`,
которые создают/меняют данные в Bitrix, в тестах подменяются (`mock_bitrix` в
`conftest.py`) — проверяется, что наш код вызвал нужную функцию с нужными
аргументами, а не то, что что-то реально ушло на портал. Читающие функции
(`get_reclamation_item` и т.п.) не подменяются глобально — кто их вызывает,
мокает сам в своём тесте.

## Поднять тестовую БД (один раз)

```bash
docker run -d --name savt-test-db \
  -e POSTGRES_USER=test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=savt_test \
  -p 5433:5432 pgvector/pgvector:pg16
```

Применить миграции (использует тот же образ Python, что и прод — версия
SQLAlchemy в `requirements.txt` несовместима с Python 3.13+, локальный venv
на новом Python для этого не подойдёт):

```bash
cd savt-backend
docker run --rm -v "$(pwd):/code" -w /code \
  --network host \
  -e DATABASE_URL="postgresql+asyncpg://test:test@localhost:5433/savt_test" \
  python:3.12-slim bash -c "pip install -q -r requirements-dev.txt && alembic upgrade head"
```

(Если `--network host` недоступен на вашей платформе — создайте свою сеть
и подключите к ней `savt-test-db`: `docker network create savt-test-net &&
docker network connect savt-test-net savt-test-db`, а в команде выше замените
`--network host` на `--network savt-test-net` и `localhost` на `savt-test-db`.)

## Прогнать тесты

```bash
docker run --rm -v "$(pwd):/code" -w /code \
  --network host \
  -e DATABASE_URL="postgresql+asyncpg://test:test@localhost:5433/savt_test" \
  python:3.12-slim bash -c "pip install -q -r requirements-dev.txt && python -m pytest -v"
```
